# SaveMaster

[English](./readme.md) | **简体中文**

一个像素工厂存档管理模组, 提供多种实用功能.

像素工厂只有一个战役存档槽位, 而所有东西都装在里面: 每个区块、每张自定义地图、你的蓝图, 以及与你进度相关的那部分设置. SaveMaster 可以把这些整体打包, 于是你可以备份它、互换它、编辑里面的地图, 并在多台设备之间保持同步.

# 功能

- 存档管理: 备份、覆盖、删除、编辑整个存档
- 存档编辑器: 不离开游戏就能编辑存档或备份中的任意地图
- 多玩家: 同一台设备上的多个玩家, 各自拥有独立的存档、蓝图、设置与云存档配置
- 云存档: 用你自己搭建的服务端在多台设备之间同步存档 (Cloudflare Worker, 或一个可在本机运行的 Python 程序)

# 要求

- 像素工厂 v136 或更新版本 (模组声明 `minGameVersion` 为 136)
- 这是一个插件型模组: 在 `mod.json` 中标记为 `hidden`, 不添加任何游戏内容, 也不影响多人联机
- 只有云存档需要联网, 其余功能完全离线可用

# 安装
本模组需要手动安装: 从 GitHub 下载发布包, 再导入游戏.

1. 打开 [releases 页面](https://github.com/DSFdsfWxp/savemaster/releases), 下载发布好的 `.zip`
2. 进入游戏: `模组` -> `导入模组`, 选择该文件
3. 如果提示需要重启游戏, 就重启

模组源码位于 `/src`. 如果你想直接运行源码, 把 `/src` 里的内容复制到模组目录下名为 `savemaster` 的文件夹中即可.

# 使用

所有功能都在 `设置` -> `SaveMaster` 下, 共 3 个入口: `存档管理`、`多玩家`、`关于`, 下文逐个说明. 模组界面跟随游戏语言, `关于` 中会显示当前版本与更新内容.

## 存档管理

第一行是当前存档. 第二行会告诉你云存档是否启用 (`云端` 表示启用, `本地` 表示未启用), 这一行有两个按钮:

- 备份当前存档. 会先让你输入名称 (留空则叫 `未命名`), 然后把所有东西写入 `saveMaster/saves` 下的一个 `.smsf` 文件
- 编辑当前存档中的地图 (见下)

分隔线下面是备份存档列表. 每一项显示名称、备份时间与文件数量, 并有三个按钮:

- 覆盖当前存档: 用这份备份替换你现在的存档. 它是彻底的覆盖: 正在玩的地图会先被关闭并保存, 游戏 `saves` 与 `schematics` 文件夹会被清空, 备份中的文件被写回, 打包在其中的设置被应用, 然后游戏会重新加载存档列表与科技树
- 编辑这份备份中的地图 (见下)
- 删除这份备份文件

备份就是普通文件, 你可以手动把它们在设备之间搬运. 任何丢进 `saveMaster/saves` 的 `.smsf` 都会出现在这个列表里. 模组读不了的文件会被跳过, 原因会打印到游戏日志中.

## 编辑存档中的地图

这个对话框会列出你所选存档中的每一个 `.msav`, 并把它们交给游戏自带的编辑器打开.

- `分类:` 按钮循环切换分类: `全部`、`自定义地图`, 然后是存档中拥有区块的每个星球
- `备份:` 按钮显示或隐藏 `-backup` 地图
- 点击一张地图就会打开游戏编辑器. 游玩、笔刷、保存, 一切都和平常一样
- 离开编辑器时改动会被写回: 编辑当前存档时直接写进 `.msav`, 编辑备份时写进备份文件 (关闭对话框时会重新写入整个 `.smsf`)
- 区块名称取自游戏内容, 因此一个区块会显示为 `星球 区块 <id> <名称>`

## 多玩家

每个玩家都是一个独立的档案, 于是两个人 (或者两个存档) 可以共用一台设备而不必抢同一个存档. 这里的 `多玩家` 指的是本机上的多个档案, 与联机无关.

- 第一次运行会给你一个 `默认玩家`
- 每个玩家拥有自己的游戏存档、蓝图、设置、备份与云存档配置
- 玩家不会各自拥有联机身份: 这里创建的玩家共用同一个 UUID, 也就是游戏在联机中使用的身份标识. 切换玩家不会改变它, 本模组也不提供修改或重置 UUID 的功能, 因此无论你使用哪个玩家, 服务器看到的都是同一个身份
- 星球对话框每次出现时, 都会有一条淡入提示显示当前玩家的名称
- 本页面提供 `添加玩家`、重命名 (铅笔)、`切换玩家` 与删除 (垃圾桶). 你不能切换到或删除自己正在使用的玩家, 两个玩家也不能同名
- 切换会先把当前玩家打包, 再解开你选择的玩家, 然后重新加载存档、蓝图、区块与科技树. 这需要一点时间, 并且请不要在联机游戏中这么做

## 云存档
### 在 cloudflare 上部署
使用 cloudflare 的 worker 和 kv 搭建免费服务器. 所需代码位于 `/cloud`

1. 确保你拥有 cloudflare 账户
2. 创建一个 worker
3. 创建一个 kv
4. 将 kv 绑定到 worker, 变量名为`db`
5. 为 worker 创建环境变量 `key`, 并在其中写入访问此服务器的密钥 (密钥相当于密码)
6. 把 `/cloud/worker.js` 中的代码粘贴到 worker 中 (先删掉 worker 里原有的代码), 然后部署

这套实现允许 25 MiB 的存档与 512 字节的存档名称, 想要别的数字就改 `worker.js` 里的 `limit`.

`/cloud/local.py` 是一个基于 FastAPI 的小服务端, 可以在你自己的机器上运行, 详见 [cloud/readme.md](./cloud/readme.md).

### 在游戏中配置

1. 设置 -> SaveMaster -> 存档管理 -> 云存档选项
2. 在 `服务器地址` 处粘贴你的 worker 的 url (比如 `example.workers.dev`); 如果不写 `https://`, 模组会替你补上. 注意在大陆地区 `*.workers.dev` 可能无法直连, 这种情况下需要绑定自己的域名
3. 填入你在部署 worker 时设置的密钥 (环境变量 `key`)
4. 为你的存档取个名字. 注意在不同设备设置同一存档名称则它们共用一份云存档槽位 (链接到同一份云存档)
5. 启用云存档 (显示 `云存档: 启用` 时就是启用了)
6. 保存配置

`测试` 会检查服务器是否有响应、是否接受你的密钥; `清除` 会删除服务器上的云存档. `上传`、`下载` 与 `清除` 都要求配置已经保存, 所以改动之后请先按 `保存配置`.

### 同步
只有当服务器地址、密钥、存档名称都已填写, 并且云存档已启用时, 云存档才会生效.

- 游戏客户端加载完成后, 会询问你是否下载云存档. `下载` 会用云端存档覆盖本地存档
- 退出战役回到菜单时, 会询问你是否上传. `上传` 会把当前存档打包 (和备份做的是同一件事) 并推送到服务器
- 作为联机客户端时不会进行任何同步

上传与下载都会覆盖另一边, 所以不要把两份不同的进度指向同一个存档名称.

### 注意
- 存档名称必须能装进服务端的 `maxNameSize`, 否则配置会被拒绝; 大于 `maxPayloadSize` 的存档会在上传时失败. 这两个数字都由客户端从服务端的 `/limit` 读取
- 密钥是以普通请求头传输的, 请使用 `https://`
- 从未上传过任何东西的设备无法下载云存档: 请先从这台设备上传一次 (或者手动把存档搬过去). 已知的表现是出现类似 `Too much data for declared Content-Length` 的错误

### 协议
你也可以自己写一个服务端, 只需要实现这套协议即可.

每个请求都通过 `key` 请求头携带密钥, 密钥不匹配时应返回错误状态码 (仓库自带的 worker 返回 `403`). `time` 形如 `20240101123000`, 取自游戏的本地时钟. 客户端使用浏览器风格的 `User-Agent`, 并最多等待一小时.

### read
功能: 读取存档  
接口: `/read`  
方法: `GET`  
携带Header:

- `key`: 访问服务器的密钥
- `name`: 存档名称
- `time`: 上次同步存档的时间, 形如`20240101123000`, 用于判断是否需要更新存档 (首次读取时不会携带)

返回: 如果传入的`time`比服务器上的新, 则请求仅返回 `304`. 如果服务器上找不到名为`name`的存档, 则请求仅返回 `404`. 否则返回存档文件, `Content-Type` 为 `application/octet-stream`.  
模组把 `304` 与 `204` 视作同一件事 (无需动作), 所以对不存在的存档返回 `204` 也可以, 仓库自带的 worker 就是这么做的.

### write
功能: 写入存档  
接口: `/write`  
方法: `POST`  
携带Header:

- `key`: 访问服务器的密钥
- `name`: 存档名称
- `time`: 存档创建时间
- `Content-Type`: `application/octet-stream`

携带载荷: 存档文件  
返回: 写入成功则返回`200`  
服务端需要把载荷与 `time` 一起保存, 因为下一次 `/read` 会拿它来比较.

### remove
功能: 删除存档  
接口: `/remove`  
方法: `GET`  
携带Header:

- `key`: 访问服务器的密钥
- `name`: 存档名称
返回: 删除成功则返回`200`  

### limit
功能: 获取服务器限制  
接口: `/limit`  
方法: `GET`  
携带Header:

- `key`: 访问服务器的密钥

返回服务器限制(仅包含`maxPayloadSize`和`maxNameSize`), `Content-Type` 为 `application/json`, 例如:

```json
{
    "maxPayloadSize": 26214400,
    "maxNameSize": 512
}
```

`maxPayloadSize`: 最大存档大小 (字节).  
`maxNameSize`: 最大存档名称大小 (字节).

### 示例
用 `curl`, 配上一份你手动导出的存档:

```bash
# 检查密钥并读取限制
curl -i -H "key: your-key" https://example.workers.dev/limit

# 上传存档
curl -i -X POST \
  -H "key: your-key" -H "name: my-save" -H "time: 20240101123000" \
  -H "Content-Type: application/octet-stream" \
  --data-binary "@my-save.smsf" \
  https://example.workers.dev/write

# 再下载回来 (worker 把不带 time 视作"有什么就给我什么")
curl -o my-save.smsf -H "key: your-key" -H "name: my-save" https://example.workers.dev/read
```

# 文件格式
一份备份就是一个 `.smsf` 文件 (SaveMaster save file), 一个小的二进制包:

```txt
'SMSF'                 魔数, 4 字节
int                    版本, 目前是 100
UTF                    存档名称
int                    年
byte x5                月, 日, 时, 分, 秒
int                    文件数量
然后重复 文件数量 次:
  UTF                  文件名
  long                 文件大小
  byte[文件大小]       文件内容
```

包内的文件名可以指向存档文件夹之外:

- `xxxx.msav`: 一张地图
- `../schematics/xxxx`: 一份蓝图
- `$setting`: 打包的游戏设置
- `../saveMaster/config/cloudsave.json`: 云存档配置, 切换玩家时使用
- `../saveMaster/saves/xxxx.smsf`: 一份备份, 切换玩家时使用

# 文件与目录
模组把自己的文件夹放在游戏 `saves` 文件夹的旁边:

```txt
Mindustry/
  saves/                 # 游戏存档 (覆盖当前存档时被清空重写)
  schematics/
  maps/
  saveMaster/
    saves/               # 你的备份 (*.smsf)
    players/             # 玩家档案
    config/              # cloudsave.json, player.json, editor.json
    tmp/                 # 编辑地图时使用的临时文件
```

游戏运行时会读取这些文件夹, 所以手动搬运文件之前请先关闭游戏.
